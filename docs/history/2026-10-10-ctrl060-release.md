# CTRL-060: the installed SDK checked outside the checkout, and a PC release manifest

The RT half of a release already existed: `tools/inspect/deployment.py --render` writes the RT package (units, hashes of
binaries/libraries/scripts, the arm_control commit it was built from) and its `install.py` applies and rolls back on the
box (`--apply`, rollback, `--check-host`; an operator step). This slice adds the two missing pieces.

* Library `tools/check/check_installed_sdk.py` (in the suite beside the other fake-server checks): builds this library's
  wheel from a scratch copy of the sources (no build isolation, no network, nothing written into the tree), installs it
  `--no-deps` into a scratch virtualenv that sees the base environment's site-packages but not this checkout, asserts
  `arm_control` is imported from the venv, and runs `check_sdk_supervisor.py` (a copy, from a scratch directory) with that
  interpreter: the SDK drives a supervisor (spawned from the checkout, as a deployment's full environment) and the C++
  fake RT server. The conda base environment has no `arm_control` installed, so only the wheel can satisfy the import.
* Project `tools/inspect/release.py` (`arm_control.release/v1`): the three commits, each required clean (untracked files
  count), reachable from `origin/implementation/control` or `origin/main` as last fetched (the fetch time is recorded; a
  task branch never counts) and equal to the project's submodule pins; the wire versions (RT protocol 5, pose hold 6, reference 7, Cartesian 8,
  supervisor contract 1, stream 1); Python, every installed distribution and where a bare interpreter resolves `arm_control`/`assembly`/`perceptions`/
  `arm_rt_servo`/`pylibfranka`/`mujoco`; sha256 of every `configs/entries/real_*`
  RESOLVED config, the instance registry and the model bundles; with `--rt-package`, the rendered package's deployment.json
  hash and its source commit, which must equal the PC's arm_control, its registry hash, which must equal this
  instances.yaml, no trial override or reference opt-in, and a hash for every binary (`--artifacts`). The capability list says software availability only:
  every hardware entry is `hardware_qualified: false`; the bench session owns qualification. Exit 1 when not publishable.
  Written under `$ARM_CONTROL_EXPORT_ROOT/<date>/release-<time>/` (CTRL-010), never into a repo. `--self-check` (project
  suite) covers dirty, off-origin, off-pin and a mismatched RT package.

Review round 1 (Opus xhigh, PASS-WITH-FIXES): MUST: under the suite's environment (PYTHONPATH = the library) pip saw an
in-tree `arm_control.egg-info` (left by an earlier in-tree build) as "already installed" and skipped the wheel -> every
step of check_installed_sdk runs without this checkout on its path, the install is `--force-reinstall`, pip never reaches
an index; reproduced with a stale egg-info present (passes), the leftover deleted. SHOULDs taken: the RT package's
registry hash, trial overrides and unhashed binaries; "on origin" means an integration branch, not any remote ref (a
deleted task branch's stale ref no longer counts); untracked files make a tree dirty; all distributions and bare-interpreter
import origins recorded; `git --no-optional-locks`. Left: `check_sdk_supervisor`'s scratch directory is not removed
(pre-existing); exit 1 means both "not publishable" and a tool error.

Not done (CTRL-060's full acceptance, beyond this slice): a capability matrix per robot/mode/profile/load/host with
"disabled" for the unsupported force/shared-object/DM combinations (here: per hardware entry, software availability
only); carrying deployment.py's BLOCKERs (dual_franka's shared CPU/exclusive pair) into the manifest; compiler/build
options and native shared-library resolution in the install layout; the operator's apply/rollback on the box, the host
check transcript and the release manifest of the set actually deployed (bench session).
