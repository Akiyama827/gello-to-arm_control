# The dual pair on its supervisors, virtual coupling everywhere, one scheduled start stamp (CTRL-053)

Operator decisions 2026-10-09: full dual-arm migration now; shared-object coupling virtual in simulation as on hardware
(empty Hands, the plate inferred from both TCPs); pair legs start with a scheduled release.

Retired (each had one replacement):
* `multi_arm/simulation.py` (`SharedSimulation`: two in-process controllers on one MuJoCo world, physical welds) ->
  the simulated pair on two supervisors: `multi_arm/world.py` (`build_pair_world`, a `WORKCELL_BACKEND_FACTORY`: both
  arms, gravity compensated, arm-arm contact, each arm's fingers; the object is not in the physics) hosted by the first
  arm's supervisor, the second a `--cohost`; each serves its own sim Hand (`rt.hand_port` +10 per arm).
* `multi_arm/hardware.py` (`RemoteHardware`: two in-process controllers over direct RT links) -> one supervisor per arm
  (`plant rt`). `SupervisedHardware` is the console's only runtime, in both cases.
* `SharedReferenceClock` (one PC reference epoch for two in-process controllers) -> scheduled_release/1 (below).
* Physical coupling: `SharedObject.virtual`/`support`/`grasp_welds`, weld composition, `paused`, the console's
  grasp/support confirmations and Hand-width entry gate, the UI's physical branches. `shared_object.virtual: true` is
  required at load. `check_dual_modes` (welds/support only) deleted; its virtual flow is covered by check_dual_hardware
  and check_cooperative.

New:
* `multi_arm/launch.py`: `stage_pair` (per-arm supervisor configs + a derived pair config, sim or RT), `start_pair`,
  `running_pair`; the console finds the supervisors through `ARM_CONTROL_PAIR_SOCKETS`. `examples/run_console.py --dual`
  starts the simulated pair; the project's `run.py sim|real dual` does the same for its bench.
* scheduled_release/1: `ArmClient.release(execution_id, start_at=Stamp)`; the supervisor (offered when its controller owns
  the trajectory clock, i.e. not native) refuses a stamp on another clock or outside `GROUP_MIN_LEAD_MS`..`GROUP_BUDGET_S`
  ahead (the approved CTRL-040 bounds), and the controller anchors the leg there (`ArmController._release(start=)`; the
  reference holds its first point until then). `SupervisedHardware.release_context` stamps both members one budget ahead
  of the first supervisor's clock. Measured: a late partner release (40 ms sim pair, 20 ms fake-RT pair) -> reference
  starts 0.00 ms apart; a scratch run without it showed 54 ms mid-phase skew for a 40 ms late release. Residual: up to one 10 ms controller tick (the supervisors tick
  independently). A native supervisor refuses it (an RT-side start is group/1).
* Supervisor trace/1 rows now carry `trajectory_elapsed_s` (the reference time was never passed).
* `align_feedback` reports `received_at`; `SupervisedHardware`'s idle-gap recovery budget runs from it, not from the call
  (re-aligning unchanged packets renewed the 50 ms budget; the retired runtime had this right).
* `MuJoCoBackend` gripper calls take per-actor finger indices (`ScenePlant.finger_indices`); `SimLink` clock domain is the
  PC's (`monotonic_domain()`).
* `arm_rt_server --fake-q0 Q1,..` (fake backend only, exactly `--n` values): the fake's start pose, so an FR3-envelope
  supervisor can ARM it.
* The console records its fault trace for every pair (the `remote_rt` gates are gone).

Checks ported: check_dual_hardware (console over two supervisors + two fake RT servers, the project's staged bench pair),
check_pair_planning (supervised sim pair, one start stamp), check_cooperative, check_dual_console (Hands are unmeasured
while a stop is unconfirmed: the waits allow it), check_bimanual_sync (idle wait on SupervisedHardware), check_supervised_hardware,
project check_dual_bench. Fixed on the way: `rt/stream_supervisor.py` expected the extension set before load_model/1
