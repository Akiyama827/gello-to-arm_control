# CTRL-033 and CTRL-022 after CTRL-053: records, the last in-process controller paths, the bench config's restatements

CTRL-053 put every graph and the dual pair on supervisors; this slice records what that closed and removes what it left
unused.

CTRL-022 (headless supervisor + SDK). Its open items are closed in software:
* Dora/console callers off the SDK: every graph (library `sim_franka_motion`, `real_franka_motion`, `sim_view_arm`; project
  `sim_bench`, `sim_workcell_add`, `real_workcell_add`, `real_franka_workcell_motion`, `calibration_workcell`) runs
  `supervised_arm` (`supervisor/dora_arm.py`, an `ArmClient`); the `arm_controller` node was deleted 2026-10-09.
* `multi_arm.simulation` direct construction and `RemoteHardware` pair execution: deleted with the sim pair (2026-10-09);
  the pair runs on `SdkArmHandle`s.
* The supervisor runtime is now the only host of an `ArmController` (`control/factory.build_arm_controller` has one caller).
* Leases/group reservation stay with CTRL-040, as recorded.

CTRL-033 (admission/fallback). The console adapter (`supervisor/console_adapter.py`) is wired: `supervised_arm` and
`SdkArmHandle` route the Dora `control` gain/Soft/payload fields through it, and jog is setpoint/1 (the supervisor's deadman,
hold at the measured pose on expiry). Remaining, hardware only: the operator console session (the adapter gates' last item)
and F5 (non-zero payload in stream mode stays refused until hardware qualification, operator 2026-09-30, 2026-10-09).

Retired (each had one replacement):
* `ArmController.run` (the Dora node loop: input dispatch, the `plan_replay`/`control_replay` aliases, a 100 Hz
  deadline schedule) -> the supervisor's servo loop (`supervisor/runtime.py`, one tick after a stall, never a catch-up
  burst) and `dora_arm`'s own alias table. Its check (`check_execution_policy.check_deadlines`: command spacing under a
  1 kHz input flood and a 40 ms stall) went with it; the mixed-clock refusal it also asserted stays
  (`check_clock_rule`).
* `QueueControllerNode.inject`/`next`: only `run` read them.
* `multi_arm.LocalArmHandle` (an `ArmHandle` over an in-process controller; its production users were the deleted pair
  runtimes) -> `SdkArmHandle`. It now lives inside `tools/check/check_bimanual_contract.py`, its only caller, as the
  coordinator's device-free harness; it is no longer exported.

Project (bench config, no value changed): `configs/simulation/franka_bench.yaml` restated the seven groups the config
duplicates check marked OPEN (step 4b): the Hand task, the pick choreography (confirm phases, phase gains, cloud
obstacles, meshes, module id), the camera processing, the base's placement, the arm's mount, the completion tolerances.
It now includes their homes (`robots/franka/control.yaml`, `workcells/franka_single_arm_nominal.yaml`,
`workcells/franka_pick_fixtures.yaml`, `sensors/franka_cameras.yaml`, `tasks/franka_hand.yaml`, `tasks/franka_pick.yaml`).
The resolved config was compared before/after: every existing value is unchanged; the includes add keys nobody in
`sim_bench` reads (`perception.{board,static,wrist,tags}`, `module_grasps.row_module.pregrasp_offset_m` (the coordinator
prefers the bench's `pregrasp_offset_base`), `scene.base.hold_q` (= `sim_base_hold_q`, [0, 0])) or that equal the factory
default (`arm.settle_timeout_s` 5.0, `arm.settle_dwell_s` 0.2). No OPEN group is left in `config_duplicates_allowed.yaml`.
